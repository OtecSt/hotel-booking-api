# Hotel Booking API

Учебный проект МИФИ. Четыре приложения запускаются независимо. Через Gateway можно зарегистрироваться, войти, посмотреть свободные номера, забронировать номер и отменить свою бронь.

| Приложение | Порт | Назначение |
|---|---:|---|
| `eureka-server` | 8761 | Реестр сервисов |
| `api-gateway` | 8080 | Входная точка REST API |
| `hotel-service` | 8081 | Каталог, интервалы занятости и статистика. База `hotel` в H2 |
| `booking-service` | 8082 | Пользователи и бронирования. База `booking` в H2 |

## Сборка и запуск

Установите JDK 21 и проверьте, что `./mvnw -v` показывает эту версию Java. Maven Wrapper сам загружает нужную версию Maven.

```sh
./mvnw verify
```

Запустите Eureka и дождитесь ответа `UP` на `http://localhost:8761/actuator/health`.
Затем запустите остальные приложения. Каждую команду выполняйте в отдельном терминале из корня репозитория.
Для Hotel и Booking задайте одинаковое значение `HOTEL_BOOKING_JWT_SECRET` длиной от 32 байт.
Сгенерируйте локальный секрет командой `openssl rand -hex 32` и задайте его в обоих терминалах через `export`.

```sh
java -jar eureka-server/target/eureka-server-0.1.0-SNAPSHOT.jar
java -jar hotel-service/target/hotel-service-0.1.0-SNAPSHOT.jar --spring.profiles.active=demo
java -jar booking-service/target/booking-service-0.1.0-SNAPSHOT.jar
java -jar api-gateway/target/api-gateway-0.1.0-SNAPSHOT.jar
```

Откройте [панель Eureka](http://localhost:8761/) и проверьте регистрацию трёх клиентов.
После регистрации обновление списка сервисов на Gateway может занять до минуты.
Для локальной проверки доступности используйте `/actuator/health` на порту каждого приложения.

## Проверка бронирования

После запуска с профилем `demo` выполните сквозную проверку через Gateway. Нужен Python 3 без дополнительных пакетов.

```sh
python3 scripts/smoke-test.py
```

Проверка регистрирует двух пользователей, входит, проверяет доступность номеров,
создаёт и отменяет бронь, повторяет запрос с тем же ключом и отправляет два
параллельных запроса на один номер. Для второго адреса Gateway задайте `GATEWAY_URL`.

| Метод и путь | Назначение |
|---|---|
| `POST /api/auth/register`, `POST /api/auth/login` | Передать `username` и `password`, получить `accessToken` |
| `GET /api/hotels` | Список отелей |
| `GET /api/rooms`, `GET /api/rooms/recommend` | Свободные номера на `startDate` и `endDate`, в том числе с сортировкой по `timesBooked` |
| `POST /api/bookings` | Бронь с `roomId`, `startDate` и `endDate`. Нужен заголовок `Idempotency-Key` |
| `GET /api/bookings`, `GET /api/bookings/{id}` | История с параметрами `page`, `size` или просмотр своей брони |
| `DELETE /api/bookings/{id}` | Отмена своей брони |

Кроме регистрации и входа, запросы требуют `Authorization: Bearer <accessToken>`.
Дата выезда свободна для следующего заезда. Повтор запроса с тем же ключом и
телом возвращает ту же бронь. Повторное использование ключа с другим телом даёт `409`.
Текущее поле `timesBooked` отражает число действующих резервов на номер.
